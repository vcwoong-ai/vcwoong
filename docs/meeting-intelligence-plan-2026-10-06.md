# DealMind 유료 미팅 기록 개발 현황

## 2026-10-07 파일 업로드 우선 범위

사용자는 브라우저 직접 녹음보다 기존 앱의 녹음 파일 업로드를 첫 출시로 선택했다. 업로드 화면은 파일 선택을 먼저 제공하고 제목은 비워 두면 파일명을 사용한다. 참가자와 3,000자 이내의 심사역 메모는 선택 입력이다. 일시는 기본값을 확인·수정하고 처리 권한 확인 뒤 업로드한다.

메모는 Meeting.uploadMemo에 별도로 보존한다. 상세 조회와 확정 회의록 다운로드에서 사용자 입력 메모로 표시하며 목록에는 보내지 않는다. AI 전사·초안 입력과 자동 보고서 근거에는 넣지 않는다. 회의록 수정·확정에도 원래 업로드 메모를 유지하고 회의 삭제·미완료 업로드 만료·상위 딜 삭제 정리 시 제거한다. 동일 요청의 메모 변경은 중복 생성과 같이 거절한다.

운영 적용에는 기존 회의 patch 다음에 `prisma/patches/2026-10-07-add-meeting-upload-memo.sql`을 적용해야 한다. SQLite와 전용 격리 PostgreSQL에서 저장·기본값·길이 제한·조회 범위·내보내기·삭제를 검사했다. 운영 DB와 기존 dev.db에는 적용하지 않았고 직접 녹음이나 실제 유료 전사 호출을 추가하지 않았다.

2026-10-06 개발 기록이다. 사용자가 미팅 기록 기능을 제안하고 배포 전 확인 외에는 질문 없이 개발을 이어가도록 요청했다. 녹음 파일 업로드, 전사, 회의록 검토·확정, 내보내기의 첫 구현과 격리 DB 검증을 완료했다. 실제 음성의 공급자 호출·브라우저 검증·판매 플랜 활성화·운영 배포는 미완료다. 직접 녹음과 기존 자료 대조·보고서 반영은 후속 범위다.

## 목표로 하는 고객 업무

딜 상세의 ‘미팅 기록’에서 회사를 만난 기록을 추가한다. 녹음 파일 또는 이후 제공할 직접 녹음으로 전사를 만든 뒤, 사람이 발언자·숫자·단위를 정정하고 회의록을 확정한다. 확정한 기록에서 투자 판단에 중요한 주장, 기존 자료와 상충하는 항목, 미확인 사항과 추가 자료 요청을 골라 딜에 연결한다. 보고서의 기존 문구나 승인 상태를 자동으로 덮어쓰지 않는다.

예를 들어 대표가 18분 42초에 ‘올해 매출 30억 예상’이라고 말했다면 원본 위치와 함께 ‘경영진 진술·전망·검증 전’으로 남긴다. 기존 IR의 전년도 매출 20억과 기간이 다르면 충돌로 판정하지 않는다. 같은 기간의 다른 값이면 두 근거를 나란히 제시하고 고객이 확인할 자료를 정한다. 전사/회의록의 확정은 사실 검증이나 투자 승인과 다르다.

## 첫 출시와 후속 범위

| 단계 | 제공할 기능 | 완료 기준 |
| --- | --- | --- |
| 1 | 기존 녹음 파일 업로드, 딜 연결, 비공개 원본 보관, 처리 상태, 타임스탬프 전사, 수정 가능한 회의록 초안 | 합성 오디오와 승인한 검증 자료의 업로드→전사→수정→확정 흐름, 재시도와 권한/한도 검사 통과 |
| 2 | 핵심 주장·지표·리스크·미확인 사항·다음 행동, 기존 문서와 대조, 보완 자료 요청, 선택한 근거의 보고서 반영 | 숫자·기간·단위와 녹음 위치가 유지되고, 미검증 발언을 확정 사실로 승격하지 않음 |
| 3 | 브라우저 직접 녹음, 일시정지, 녹음 복구, 모바일 동작, 발언자 정정 | 권한 거절·백그라운드 전환·종료/업로드 실패 시 자료 손실과 오해를 방지하는 실제 기기 검증 |

화자 구분의 자동 번호는 사람의 이름과 동일하지 않다. 사용자가 참가자 이름과 연결하고 검토한 뒤 확정한다. 고객의 음성 자료를 합성 자료로 대신 검증했다고 주장하지 않는다.

## 기존 제품에 연결하는 방식

VC는 `Deal/Document/Report`, PE/M&A는 `MADeal/MADocument/PEEvidence/PEEvidenceRequest`를 사용한다. 기존 문서 업로드를 오디오 업로드로 바꾸지 않고 공통 Meeting 계층에 각 트랙의 딜을 연결했다. 기존 권한과 딜 소유자의 유효 구독 판정을 재사용한다.

첫 모델은 Meeting(참가자/일시/딜/원본/해시/기간/작업 lease/불변 원본 전사), MeetingRevision(회의록 이력), MeetingUsageAdmission(시간 예약/정산)이다. 신규 VC/PE 연결은 하나이며 양쪽 동시 연결은 PostgreSQL patch의 CHECK 제약으로 차단한다. 상위 딜 삭제 시 연결이 비워져 접근을 거절하고 작업 실행기의 정리 작업이 본문·참가자와 원본을 제거한다. 사용량 원장은 유지한다. PostgreSQL additive SQL과 SQLite schema를 작성하고 격리 DB에서만 적용했다. 기존 합성 dev.db와 운영 DB에는 적용하지 않았다.

현재 원본 전사는 불변이며 회의록 본문·주장·확인 근거·질문·다음 행동을 수정할 수 있다. 저장과 확정은 새 버전과 이력을 남기며 확정본을 수정하면 초안으로 돌아간다. 정정 전사, 보고서 인용과 과거 근거의 차이 표시는 후속 범위다.

## 구현한 첫 버전과 실행 조건

- VC·PE 딜 상세에서 `/meetings/vc/{dealId}`, `/meetings/pe/{dealId}`로 연결한다. 읽기는 기존 팀 범위, 생성·수정·확정은 딜 쓰기 권한과 소유자의 현재 유료 구독을 함께 검사한다. 구독 만료 뒤에도 기존 기록 읽기·삭제는 허용한다.
- 비공개 Blob 직접 업로드는 24MiB, 개발용 local 업로드는 4MiB까지다. MP3/WAV/M4A/MP4 오디오/WebM/OGG의 이름·MIME·서명·크기와 원본 해시를 검증한다. 별도 작업 실행기의 FFprobe가 실제 오디오 스트림과 길이를 검사한다. 긴 파일 분할, S3 직접 업로드, 직접 녹음은 구현하지 않았다.
- 전사는 OpenAI `whisper-1`, 초안은 `gpt-4o-mini`를 사용하는 어댑터를 구현했다. 전사 원본, 타임스탬프, 초안, 미검증 주장, 자료 요청·다음 행동을 보존한다. 자동 초안의 주장은 항상 미검증이다. 실제 공급자 호출과 한국어 품질·비용 평가는 아직 수행하지 않았다.
- 원본 재생은 딜 권한을 검사하는 인증 경로만 사용한다. 확정된 회의록만 Markdown으로 내보내며, 확정이 독립 사실 검증을 뜻하지 않는다는 안내를 포함한다. 원본 저장 주소와 키는 목록·내보내기에 노출하지 않는다.
- 한도는 소유자별 한국 시간 기준 월 원장에 예약한다. 파일 하나를 먼저 최대 허용 시간만큼 예약한 뒤 실제 길이로 정산하므로 월 잔여 시간이 파일 최대 시간보다 작으면 업로드를 시작할 수 없다. 공급자 호출 전 거절은 예약을 해제하고 호출 뒤 불확정 결과는 사용량을 보존한다. 삭제와 상위 딜 삭제는 이미 사용한 한도를 되돌리지 않는다.
- 업로드 권한은 15분, 미완료 업로드 예약은 20분 이후 정리한다. 삭제 시 본문·참가자·제목·원래 파일명·회의록 이력을 제거하고 원본 삭제 실패는 작업 실행기가 다시 처리한다. 완료되지 않은 업로드의 원본 정리는 업로드 권한 만료보다 늦게 실행한다. 이 정리는 작업 실행기가 계속 실행 중이어야 진행된다. 자동 보관 기간 만료나 UNKNOWN 결과의 운영자 조정 화면은 후속 범위다.

기능은 기본 꺼짐(`MEETING_INTELLIGENCE_ENABLED=0`)이다. 월 시간과 파일 최대 시간을 명시하지 않으면 열리지 않는다. 파일 시간 상한은 60분 이내이며 판매 가격·포함 시간을 임의로 정하지 않았다. `.env.meetings.example`은 키 없는 예제다. 실제 키는 Git 무시 파일이나 공급자 비밀 설정에만 넣는다.

```powershell
npm run meetings:worker                 # 설정 존재만 확인; DB·유료 API 호출 없음
npm run meetings:worker -- --run-once    # 준비된 환경에서 정리와 작업 하나 실행
npm run meetings:worker -- --watch       # 별도 실행 환경에서 직렬 작업·정리 반복
```

실행 모드는 격리 DB에 SQL patch 적용, 비공개 저장소, `MEETING_OPENAI_API_KEY`, 절대 경로 `MEETING_FFPROBE_PATH`, 기능 활성화와 명시적 시간 한도가 모두 필요하다. Next.js 앱과 별도 작업 실행기에 동일한 격리 DB·저장소·한도를 연결해야 한다. Vercel 일반 요청에서 장시간 전사를 처리하지 않는다. 별도 작업 호스팅은 아직 구성하지 않았다. 공급자 호출의 자동 재시도는 꺼져 있고 lease를 잃은 실행기의 결과 기록을 차단한다. 초안 작성만 실패하면 전사를 보존해 수동 회의록 작성을 허용한다.

## 검증 결과와 범위

전체 `test:all`, 앱·검사 도구 TypeScript 검사, 변경 파일 lint 및 별도 출력 경로의 Next.js 빌드를 통과했다. 새로운 모델은 격리 SQLite와 PostgreSQL 17에서 검증했다. PostgreSQL은 기존 모델만 있는 합성 기준 DB에 실제 additive SQL patch를 적용했으며 마지막 한도 예약의 동시 요청 중 하나만 성공하고 VC·PE 동시 연결은 DB 제약으로 거절됨을 확인했다. 유료·팀 권한, 동일 요청, 불확정 공급자 결과, 확정 버전 충돌, 원본 부분 재생, 삭제·한도 보존도 합성 공급자로 검사했다. 설치된 FFprobe로 생성한 1초 PCM WAV의 길이와 시간 초과 거절을 검사했다.

공급자·저장소 mock은 실제 외부 품질·전달·저장 정책을 증명하지 않는다. 브라우저 흐름, 고객 음성, 실제 전사 비용, 작업 호스팅과 운영 schema 전환은 미확인이다. 기존 `prisma/dev.db`와 운영 DB에는 새 모델을 적용하지 않았으며 앱의 기능은 계속 꺼져 있다.

## 처리·요금·보관

유료 구독의 현재 접근 가능 상태와 딜 쓰기 권한을 업로드/전사/재처리마다 서버에서 검사한다. 고객 팀 ADMIN이나 클라이언트 플랜 문자열만으로 허용하지 않는다. 딜 소유자 기준으로 월 전사 분량을 원장에 예약하고 실제 길이를 검증해 정산한다. 구독 취소·기간 만료·중복 요청·실패 재시도·보고서 삭제가 한도를 초기화하지 않게 한다. 포함 시간과 추가 사용 가격은 공급자 비용과 한국어 전사 품질을 측정한 후 정한다.

녹음 파일은 4MiB 문서 제한에 맞지 않는다. 짧게 유효한 업로드 권한을 발급해 비공개 스토리지로 직접 전송하고, 소유자/경로/해시/실제 파일형식/크기를 확인한 후 원본을 확정한다. 사용자 입력 URL을 전사 서버가 임의로 읽지 않게 한다. 원본의 전체 버퍼를 HTTP 함수 한 번에 올리거나 수십 분 처리를 일반 요청 안에서 끝내려 하지 않는다. Vercel 함수의 4.5MB 요청 제한과 별개로 서비스의 시간·크기·월 한도를 명시해야 한다.

작업은 업로드 대기→검증→전사 대기→전사 중→회의록 초안→검토/확정 상태로 처리한다. lease/CAS, 작업 ID와 공급자 요청 기록으로 중복/재시도를 통제한다. 공급자 응답이 불확실하면 ‘조회/조정 필요’로 남기고 과금 호출을 맹목적으로 반복하지 않는다. 긴 파일을 분할할 때 절대 타임스탬프와 경계 발언을 유지한다.

업로드/직접 녹음 전에 녹음과 외부 전사 처리에 대한 참가자 동의·자료 제공 권한을 확인하도록 안내한다. 비공개 원본은 인가된 사용자만 재생하고 공유 범위, 보관 기간, 원본 삭제, 전사/확정 기록 삭제를 구분해 제공한다. 외부 공급자의 보관 정책과 고객 조직의 자료 처리 조건을 확인한다. 로그에는 오디오 URL·전사 전문·개인정보·키를 남기지 않는다.

## 먼저 결정하거나 준비할 항목

1. 한국어 전사 공급자의 이용 가능 키, 자료 보관 조건과 합성 평가의 비용 상한.
2. 긴 파일을 수용하는 비공개 저장소와 비동기 작업 실행 환경.
3. 유료 플랜별 포함 시간, 파일 상한, 보관/삭제 정책과 검토 후 보고서 반영 UX.

개발과 합성 검증은 추가 질문 없이 이어가며 배포 직전에만 사용자에게 확인한다. 실제 고객 자료 전송·요금제 판매와 운영 schema 이전을 완료했다고 선언하지 않는다. 현재 어떤 기능도 유료 고객에게 활성화하지 않았다.

참고: [OpenAI 파일 전사](https://developers.openai.com/api/docs/guides/speech-to-text), [Vercel 함수 제한](https://vercel.com/docs/functions/limitations). 현재 어댑터의 모델 선택은 실제 품질 평가 뒤 바꿀 수 있다.
