# DealMind 투자 검토 데스크 디자인 검토

## 참고와 적용

[GeekNews의 디자인 작업 사례](https://news.hada.io/topic?id=34580)는 제품에 맞는 모티프를 고른 뒤 다양한 시안을 비교하고, 선택한 시각적 기준을 다른 구역에 일관되게 확장하며 반복해서 다듬는 과정을 설명한다. 이번 화면의 모티프는 투자팀이 딜과 근거를 정리하는 **투자 검토 데스크**다. 참고 사이트의 장식이나 놀이공원 주제를 그대로 사용하지 않는다.

## 네 방향의 비교

아래는 코드와 사용 흐름을 읽고 정리한 방향 비교다. 조율 담당은 별도 격리 앱의 임시 `public/design-directions.html`에 합성 데이터로 네 방향을 구현하고 브라우저에서 실제 렌더링을 확인했다고 보고했다. 이 임시 시안은 제품 소스가 아니며 실제 고객 데이터도 사용하지 않았다. 리뷰 담당은 그 화면을 직접 열지 않고 선택 근거와 구현 diff를 검토했다.

| 방향 | 적합한 점 | 주의점 | 선택에 반영할 요소 |
| --- | --- | --- | --- |
| Quiet paper | 한국어 설명과 긴 근거를 편하게 읽음 | 차단과 다음 행동의 중요도가 약해질 수 있음 | 밝고 따뜻한 본문 바탕, 낮은 장식 밀도 |
| Dark ink | 탐색과 주요 행동을 분명하게 묶음 | 본문까지 전면 어둡게 만들면 문서와 상태색이 피로해질 수 있음 | 짙은 navy 탐색 셸 |
| Dense analytical | 여러 딜의 준비 상태를 빨리 비교함 | 모바일과 처음 쓰는 사람에게 정보가 과밀해질 수 있음 | 행별 정보 구조, 숫자 정렬, 다음 행동 위치 |
| Editorial | 제목·설명·본문 계층이 명확함 | 큰 hero나 장식 글꼴이 실무 목록을 밀어낼 수 있음 | 제목과 짧은 설명의 계층만 사용 |

선택 방향은 quiet paper 본문, dark ink 탐색 셸, dense analytical 행 정보, editorial 제목 계층의 조합이다. 제한적인 muted gold는 브랜드 포인트이며 승인·완료·차단을 뜻하지 않는다. 준비 상태의 의미와 경고색은 기존 업무 데이터와 함께 유지한다. 실제 사용자 선택으로 추가 조정할 수 있다.

## 코드에서 확인한 기준

- `src/app/ma-deals/page.tsx`는 로그인과 팀 조회 범위를 확인하고 표시된 딜에 대한 readiness를 배치 조회한다. 디자인 변경이 접근 조건이나 조회 범위를 변경해서는 안 된다.
- `src/app/ma-deals/ma-deals-page-client.tsx`는 검색, 긴급도/최근 수정 정렬, 페이지 추가 로딩, 빈 상태, 보관 확인을 제공한다. 첫 페이지와 전체 목록의 개수를 혼동하지 않는다.
- `src/components/ma-deals/ma-deal-queue.tsx`는 canonical readiness와 다음 행동을 표시한다. 준비 상태 누락을 성공으로 바꾸거나 임의 점수로 채우지 않는다. 보관 버튼의 소유자 조건도 유지한다.
- `src/components/layout/app-layout.tsx`는 본문 이동 링크와 모바일 메뉴의 경로 변경/desktop 전환 닫기를 제공한다. 새 시각적 셸에서도 이 동작을 유지한다.
- `src/components/layout/header.tsx`, `sidebar.tsx`는 계정·알림·모바일 drawer·VC/PE 탐색을 포함한다. 장식 때문에 주요 행동을 숨기지 않는다.

## 변경과 리뷰의 제한

가짜 고객명, 투자금액, 성공률, 임의 readiness 수치, 근거 없는 그래프를 운영 화면에 추가하지 않는다. 장식과 실제 계산값을 명확히 구분한다. 새 통계가 일부 로딩한 딜에서 계산됐다면 그 범위를 설명한다. 비밀값·고객정보·실제 문서 내용은 이 기록에 저장하지 않는다.

키보드 focus 표시, 검색 입력의 접근 가능한 이름, 정렬의 선택 상태, 아이콘 버튼 이름, drawer의 focus/Escape 동작을 유지한다. 모바일에서 긴 기업명·한국어 상태·다음 행동이 잘리거나 가로 넘침을 만들지 않도록 점검한다. 작은 gold 글씨의 대비와 상태색만으로 의미를 전달하는 방식을 피한다.

## 실제 확인하지 않은 부분

현재 리뷰의 직접 확인은 정적 코드와 참고 글에 근거한다. 네 가지 임시 시안의 렌더링 확인과 방향 선택은 조율 담당의 보고로 확인했다. 최종 화면의 대비 측정, 스크린리더 사용, 전체 키보드 경로, 1024px 화면, 실제 사용자 선택은 아직 확인하지 않았다. 이 리뷰 담당은 소스·설정·테스트를 수정하거나 실행하지 않는다. 다른 담당의 실제 검증 결과와 구현 diff를 받은 뒤 확인한 범위만 이 문서에 추가한다.

정적 diff에서 검색 입력에 명시적 label과 검색 범위 설명이 추가됐고, 상단 집계는 불러온 활성 딜 범위를 표시하며 실제 readiness에서 계산한다. 기존 정렬·페이지 추가 로딩·다음 행동·소유자 보관 조건은 유지된다. 셸 변경은 본문 이동 링크, 모바일 drawer, focus 표시, aria 상태를 유지하고 기존 정적 전문 분야 목록을 실행 중인 에이전트처럼 표시하던 문구를 수정한다. 이는 렌더링 또는 실제 접근성 검증 완료를 뜻하지 않는다.

CSS의 선언 색상 계산에서는 작은 상태 글자의 white 배경 대비가 약 4.68 이상이었다. 공통 파란 focus outline은 navy 소개 영역에서 대비가 낮아 별도 밝은 gold outline으로 수정됐고, 움직임 감소 설정에서 행·정렬 전환을 끄는 규칙이 추가됐다. 모바일 한 열 및 중간 폭 두 열 배치, 좁은 desktop의 도메인 상태 한 열 규칙도 정적으로 확인했다. 화면의 합성 색상·실제 글자 크기·키보드 이동·zoom 결과는 이 계산과 별도로 확인해야 한다.

## 조율 담당이 보고한 임시 화면 확인

격리 앱의 합성 데이터 화면을 390×844에서 열고 모바일 메뉴를 열었을 때 닫기 버튼으로 focus가 이동하고, Escape로 닫으면 메뉴 열기 버튼으로 돌아오는 것을 확인했다. 없는 검색어의 빈 상태와 대기열 0건 표시, 검색어 제거 후 합성 딜 3개 복구, 최근 수정 정렬의 aria-pressed 전환도 확인했다. desktop에서 소개 영역이 과밀해 목록을 아래로 밀어내는 문제를 발견해 크기를 줄이는 후속 수정을 요청했다.

후속 정적 diff에서 소개 영역 padding과 제목·요약 숫자 크기·구역 간 간격이 줄었고 제목은 h1으로 정리됐다. 검색 label은 시각적으로 숨겨도 입력과 연결되어 있으며 도메인 상태는 짧은 표시와 전체 의미의 aria-label/title을 함께 가진다. 정보 계산과 권한 조건의 변경은 없다. 조율 담당은 최종 수정 후 390×844, 998×884, 일반 desktop 화면을 다시 렌더링했다. 모바일 첫 화면에 첫 딜 제목, desktop 첫 화면에 첫 행, tablet에 두 열 카드 내용이 나타나는 것을 확인했다. 이는 합성 데이터에서의 관찰이며 모든 긴 이름·확대 크기의 검증은 아니다.

이는 조율 담당이 브라우저로 직접 확인한 일부 UI 동작이며 리뷰 담당의 직접 관찰은 아니다. 운영 데이터·운영 DB를 사용하지 않았고 자동 테스트·전체 build도 실행하지 않았다. 최종 대비·스크린리더·전체 API 회귀·실제 사용자 사용성 검증 완료를 의미하지 않는다.

## 재사용 기록과 조율

Ruflo `swarm_init`, `agent_spawn`(3개 조율용 등록), `task_create`, `task_complete`, `swarm_shutdown`을 사용했다. 실제 파일 작업은 Codex 하위 에이전트가 PE 화면, 공통 셸, 읽기 전용 리뷰로 나누어 수행했다. Ruflo 등록만으로 모델 실행이 이뤄졌다고 주장하지 않는다.

민감정보 없는 기준은 Ruflo `memory_store`로 namespace `patterns`, key `dealmind-design-investment-desk-2026-10-03`에 저장했다. `memory_retrieve`로 동일 키를 다시 읽었으며 `found: true`와 저장한 방향·제약·검증 한계를 확인했다. 이번 디자인 변경은 운영에 배포하지 않았다.
