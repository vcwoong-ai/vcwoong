# 3주차 측정 설계안 — 수집 미구현

2026-10-01. 이벤트 SDK, API, DB, 쿠키, 로그, 삭제 작업은 추가하지 않았다.
아래 이벤트와 보관 기간은 사람 승인 전 제안이다. 목적은 첫 딜 생성에서 근거 확인까지 어디서 멈추는지 파악하는 것이다. 검토 완료나 투자 승인 여부를 추정하지 않는다.

## 이벤트 정의

공통 필드 후보: schema_version, 시간(시 단위), track(vc/pe/unknown), 일별 회전하는 임의 session_key. 등록 폼의 track은 안내 문맥이지 영속적인 사용자 직무가 아니다.

| 이벤트 | 발생 조건 | 추가 허용 필드 | 해석 주의 |
|---|---|---|---|
| onboarding_view | 인증 후 첫 딜 안내가 보임 | surface(dashboard/vc_list/pe_list) | 가입 성공 이벤트와 별개 |
| first_deal_dialog_open | 안내의 생성 버튼으로 대화상자 열기 | 없음 | 생성 완료 아님 |
| first_deal_create_result | 안내에서 시작한 생성 요청의 결과 | outcome(success/validation_error/server_error) | API 성공에만 success. 원문 오류 수집 금지 |
| first_input_saved | 최초 입력 저장 성공 | input_kind(vc_document/pe_financial_period/dart_import) | 업로드·저장은 검증 완료 아님 |
| decision_view | VC 보고서 결정 화면 또는 PE IC 의사결정 열기 | surface(vc_report/pe_ic) | 투자 승인·읽기 완료 아님 |
| evidence_panel_open | 실제 근거 패널 열기 | view_kind(excerpt/parsed_text) | 근거 존재·열람은 진위 검증 아님 |
| contradiction_panel_open | 실제 상충 패널 열기 | 없음 | 상충 해결·도움 여부를 추정하지 않음 |

첫 입력 여부의 중복 판정과 API 성공 연결은 구현 전 별도 설계·승인이 필요하다. 현재 저장 구조가 이를 제공한다고 주장하지 않는다. client 재시도/중복 발행은 세션 내 임의 event_key로 제한적으로 제거하는 방안을 검토한다.

## 개인정보 최소화와 접근

- 이름, 이메일, 회사명, 딜/보고서/문서/user ID, 파일명, 자유 입력, AI 프롬프트, 근거 원문, 재무 수치, 승인 판단, IP, 전체 URL/query, 토큰·쿠키, 결제 정보는 수집하지 않는다. 오류는 허용된 범주만 기록한다.
- session_key는 임의 값이고 24시간마다 회전한다. 사용자 ID를 해시한 값으로 대체하지 않는다. 해시는 익명화가 아니다. 장기 식별자와 기기 지문은 금지한다.
- 기본 설계는 세션 내 흐름 측정만 지원한다. 회사/집 컴퓨터 연결, 사용자별 재방문, 코호트 추적은 지원하지 않는다. 해당 지표는 추가 식별·동의·접근 검토 없이 도입하지 않는다.
- 운영 집계는 지정된 제품 담당자만 조회. raw 접근은 필요한 진단 담당자에게 제한하고 접근 기록/삭제 책임자를 도입 전에 정한다. 권한 엔진 변경은 이번 범위 밖이다.
- 관리자, fixture, preview/local 테스트는 집계에서 제외한다. 외부 분석 서비스 전송은 승인 전 금지한다. 사용자 고지·동의 방식은 수집 도입 전에 결정한다.

## 보관 기간 제안

| 데이터 | 기간 | 삭제/집계 원칙 |
|---|---|---|
| 세션 연결 정보 | 최대 24시간 | 회전 시 폐기, 사용자 식별 매핑 없음 |
| 최소 raw 이벤트 | 14일 | 매일 만료 삭제. 실패/원문 payload 보관 금지 |
| 일별 집계 | 90일 | 5세션 미만인 세그먼트 표시·드릴다운 금지. 식별키 없음. 세션 수는 인원 수가 아니며 소규모 내부 pilot 집계는 공개하지 않음 |
| 백업에 남은 raw | 삭제 후 최대 30일 | 복구 시 만료 데이터 재삭제, 백업 운영 가능 여부 확인 필요 |

기간과 삭제 실행자는 승인 대상이다. 현재 해당 삭제 job이나 분석용 저장소는 없다.
지표는 안내 조회 → 대화상자 → 성공 생성 → 입력 저장 → 결정/근거 열람의 세션 내 비율과 중단 지점이다. 작은 표본의 차이를 효과나 인과관계로 발표하지 않는다. 3–5명 인터뷰는 집계 지표보다 관찰 기록으로 해석한다.
