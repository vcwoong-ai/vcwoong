# PE 자료 업로드 범위와 복구

## 이번 로컬 구현

PE 데이터룸에 PDF/DOCX/PPTX/XLSX/TXT 자료를 파일당 **4MiB 이하**로 추가한다. 기존 MADocument, 파일 검증, 비공개 저장, 문서 파서와 인증된 다운로드를 재사용한다. 새 의존성/DB schema는 없다. 이 한도는 서버 multipart 경로의 제한이며 대용량 직접 업로드를 구현했다고 주장하지 않는다.

중복 예약 어댑터는 현재 프로젝트 운영 구조인 PostgreSQL의 `createMany(skipDuplicates)`를 사용한다. SQLite 업로드 런타임 지원을 추가하지 않았으며 지원하지 않는 DB에서는 오류를 반환한다. 4MiB 입력 제한과 route 60초 설정은 압축 파일의 확장 크기·파서 CPU/벽시계 한도를 모두 보장하는 장치가 아니다.

로그인과 현재 딜 편집 권한을 확인한 뒤 요청 본문을 크기 제한하여 읽는다. 업로드 작업 UUID는 사용자·딜과 함께 서버 문서 ID로 변환된다. 같은 작업의 파일 이름/MIME/유형/바이트 해시는 고정된다. DB 예약에 성공한 요청만 저장소를 쓰므로 같은 작업의 동시 요청·다른 내용 재전송이 기존 원본을 덮어쓸 수 없다. UUID 자체는 인증 권한을 대신하지 않는다.

파일 저장 후 텍스트 추출은 별도 결과다. 파싱 실패·빈 텍스트·주의가 필요한 경우 원본은 보존하고 확인 안내를 제공한다. 텍스트가 있다는 사실은 근거 검수·회계 수치 검증·AI 분석 완료를 뜻하지 않는다. 자동 재무 추출, 근거 생성, 보고서 생성은 이 업로드 작업에서 실행하지 않는다.

## 결과 미확정

- UI는 파일을 선택할 때 작업 번호를 만들고 불확정 결과 동안 파일과 유형을 고정한다. 새 작업 번호로 자동 재전송하지 않는다.
- `GET /api/ma-deals/[id]/documents?uploadId=...`는 로그인한 사용자의 해당 딜 작업만 조회한다. 원본 저장 위치·본문·해시·내부 잠금 토큰은 응답에 포함하지 않는다.
- 미등록이 확인되면 사용자 요청으로 **같은 작업 번호**만 재전송할 수 있다. 동시 원래 요청이 도착해도 DB 예약/내용 비교로 보호한다.
- 처리 중이면 상태 확인만 수행한다. 저장 결과 불확정·만료된 저장 단계는 재전송을 보류한다. 저장 함수의 네트워크 오류만으로 실제 저장 실패를 단정할 수 없다.
- 예약된 파일이 저장됐는지 확인할 수 없는 경우의 자동 조정은 아직 없다. 관리자 확인이 필요하며 임의 DB 상태 변경·파일 삭제·새 작업 생성으로 해결했다고 주장하지 않는다. 확정된 비공개 원본의 파싱 실패·만료는 아래 수동 복구 경로를 사용한다.
- 업로드 완료 뒤 자료 목록 조회가 실패하면 완료와 조회 실패를 분리하고 목록 GET만 재시도한다.

## 활성화 후 필요한 확인

운영 비공개 Blob/S3 연결·접근 정책, 실제 문서 파싱 품질·스캔본, 대용량 파일, 중단 후 자동 복구·관리자 조정, 실제 고객 팀 업무를 별도로 확인해야 한다. 기존 공개 저장 파일 이전·URL 회수는 이 기능으로 해결되지 않는다. 공급자 연결·schema 적용 목록은 `external-service-connections.md`를 따른다. 이 단계에는 운영 업로드/키·권한 변경/배포가 없다.

후속 수정에서 공통 `src/lib/prisma.ts`의 자동 query/error/warn 출력을 모든 환경에서 비활성화했다. 기존 서버 인스턴스는 재시작이 필요하다. 이번 예약의 예상된 중복 오류는 예외 대신 건수로 처리한다. 다른 애플리케이션의 명시적 로그까지 모두 검사한 것은 아니며 실제 고객 자료 사용 전 별도 검토가 필요하다. `runtime-log-privacy.md` 참조.

격리 테스트에서는 합성 파일만 사용한다. 생성한 합성 DB 행과 그 행의 비공개 로컬 파일만 정리하며 기존 파일을 삭제하지 않는다. 실제 검증 결과는 `autonomous-progress.md`와 `e2e-testing.md`에 기록한다.

## 확정된 원본의 수동 텍스트 추출 복구 (2026-10-05)

편집 권한자가 데이터룸 문서 상세를 열어 **추출 상태 조회 → 텍스트 추출 다시 시도**를 선택한다. `POST /api/ma-deals/[id]/documents/[documentId]/retry-parse`는 저장된 원본만 사용하며 새 파일·URL·해시·텍스트 입력을 받지 않는다. 로그인·현재 딜 편집 권한을 서버에서 확인한다. 공유 ANALYST는 자료 열람만 가능하며 재추출은 할 수 없다.

- 대상은 v1 업로드 메타데이터가 있는 4MiB 이하의 확정된 비공개 원본 중 WARNING 또는 만료된 PARSING이다. UNKNOWN, STORING, 메타데이터 없는 기존 자료, 4MiB 초과는 대상이 아니다. 진행 중인 PARSING은 상태만 반환한다.
- 원본의 딜/문서 저장 경로, 이름/MIME/유형/크기/바이트 해시를 확인한다. 전체 메타데이터·원본 속성 CAS로 새 토큰/10분 lease를 확보하고, 동일한 상태·토큰·유효 lease일 때만 결과를 저장한다. 이전 작업의 늦은 완료가 새 결과를 덮어쓰지 못한다.
- 기존 JSON 메타데이터에 선택적인 parseAttempts를 추가한다(기존 값 없음=0). 수동 재시도는 문서당 최대3회다. DB schema·새 의존성은 없다.
- 복구 읽기는 Blob/S3 스트림·로컬 파일을 4MiB로 제한한다. 공통 readStoredFile의 기존 기본값50MiB는 유지한다. 압축 해제 후 크기/CPU와 전체 동시 파싱 부하를 완전히 제한했다고 주장하지 않는다.
- 읽기·해시·파싱 실패 시 원본 URL과 기존 추출 텍스트를 유지하고 WARNING을 기록한다. 원본 쓰기/삭제·AI 호출·근거 변경은 하지 않는다.
- 화면은 매번 창을 열 때 최신 상태 GET을 먼저 요구한다. POST 응답 유실·실패 시에도 GET으로 상태를 확인하며 자동 POST 재전송은 하지 않는다. GET 목록에는 추출 상태/재시도 가능 여부/횟수만 추가하고 원본 URL·메타데이터·해시·본문은 제외한다. 가능 여부는 원본 상태를 의미하며 편집 권한은 별도 서버 검사한다.

실제 저장소의 접근 정책·클라우드 연결·실제 고객 문서 품질·스캔본/OCR·4MiB 초과 업로드·저장 결과 미확정의 관리자 조정과 자동 복구는 별도 확인 대상이다. 로컬 TXT 성공과 합성 저장소 테스트는 이 범위의 실서비스 확인을 대체하지 않는다.
